Partner networking project

Worked with Ty this week. Our goal was to be able to create a virtual whiteboard that would convert to g-code and then, real-time, recreates it on paper. We looked at using websockets to do this.
The provided drawing-app.tsx file (download here) is a comprehensive React component for a browser-based drawing application that supports both freehand sketching and shape drawing, along with features to export the result as G-code or SVG. The app leverages several tools and components from shadcn/ui and lucide-react libraries, and uses React state and refs extensively to manage drawing behavior and interface responsiveness. It also integrates a WebSocket connection to an ESP32-based plotter, enabling real-time plotting of pen tool strokes.
At the app's core is a canvas element, managed via a canvasRef, where all drawing actions occur. Users can draw using a pen, eraser, or geometric shapes (line, rectangle, circle, triangle), with different behaviors for each tool. The triangle tool, notably, requires three separate clicks to complete a shape. Mouse and touch events (onMouseDown, onMouseMove, etc.) capture interactions, and functions like handleStart, handleMove, and handleEnd control the actual drawing logic. For shapes, a temporary canvas previews the outline before finalizing it.
The application supports undo/redo functionality by saving canvas states as image data, which are stored in history and future stacks. Drawings are recorded in a pathData array, which allows exporting the work either as SVG or G-code. The G-code output includes configurable commands for pen-up/down, feed rate, and travel speed—making it compatible with typical plotter hardware. A settings panel lets users change these parameters, as well as view debug info.
The WebSocket integration enables sending pen strokes to a connected ESP32 plotter in real-time. The connection status and plotter parameters (IP, port, paper size) are configurable, and users can send manual commands like “Home,” “Pen Up,” and “Pen Down.” Additional features include saving and loading drawings via localStorage, clearing the canvas, and a tab-based UI for navigating between drawing tools, settings, and plotter controls.

Drawing App

This app was 98% Vercel 2% human tweaking. The program runs locally. We couldn't get the websocket to work with browser side connection because we would have had to add SSL / authentication to the ESP side of the websocket to pass snuff with the vercel-deployed HTTPS protocol. That, plus the Chrome firewall, made it a bit annoying to connect. The eventual solution was to run it locally and use Firefox for internet connection, since it does not have that firewall.
Using LLMs to develop the front end was an interesting process. We had to learn how to debug and troubleshoot--which was partially solved with AI as well. At the same time, we had to use a critical eye to understand certain errors. For example, the AI hallucinated a button that would accept an IP address, but only visually--the back-end had a static value that was not updateable. Fixing this required opening up the hood manually.

ESP Code

Here is the code
This Arduino code runs on an ESP32 and sets up a local WiFi connection along with a WebSocket server. It lets the ESP32 talk to a web app in real time. The goal is to control something physical—like a pen plotter—based on messages sent from the app.
When the ESP32 turns on, it connects to WiFi and starts listening for WebSocket connections on port 81. Once a connection is made, it waits for messages like "PEN UP," "PEN DOWN," or move commands with X and Y positions. When it gets a message, it figures out what to do and sends signals to motors or pins to move the pen or do other actions.
Thus, this code lets a web-based drawing app control a physical drawing device through live WiFi commands.
